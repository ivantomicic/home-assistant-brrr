# Brrr Notifications for Home Assistant

A custom Home Assistant integration that turns [Brrr](https://brrr.now/) into a native visual automation action.

[![Open your Home Assistant instance and open this repository in HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=ivantomicic&repository=home-assistant-brrr&category=integration)

## Features

- UI setup; no webhook secret in automation YAML.
- Multiple shared or device-specific Brrr webhook targets, selectable together.
- Native **Brrr: Send notification** action in the visual automation editor.
- A **Send test notification** button for every configured target.
- Title, subtitle, message, thread ID, sound, interruption level, critical volume, Focus filter, expiration, icon, image, and open URL fields.
- Public HTTPS URLs or opt-in images selected from Home Assistant's Media Library.
- Translated action labels, friendly option names, and native Home Assistant icons.
- Clear errors and bounded retries for authentication, rate-limit, server, timeout, and connection failures.
- Redacted diagnostics.

## Installation

### HACS

1. Open the HACS badge above, or open **HACS → Integrations → Custom repositories**.
2. Add `https://github.com/ivantomicic/home-assistant-brrr` as an **Integration** repository.
3. Install **Brrr Notifications** and restart Home Assistant.
4. Open **Settings → Devices & services → Add integration** and search for **Brrr Notifications**.

### Manual

1. Copy `custom_components/brrr` into your Home Assistant configuration directory as `/config/custom_components/brrr`.
2. Restart Home Assistant.
3. Open **Settings → Devices & services → Add integration**.
4. Search for **Brrr Notifications**.
5. Paste a shared or device-specific webhook URL from the Brrr app and give the target a name.

The setup flow validates the webhook format without sending anything. After setup, open the target's device page and press **Send test notification** to perform a real delivery test.

## Visual automation action

In an automation, add an action and search for **Brrr: Send notification**. Select one or more configured Brrr targets, enter the message, and expand the optional appearance or delivery sections only when needed.

Example YAML generated by the visual editor:

```yaml
- action: brrr.send_notification
  data:
    target_device_ids:
      - IVAN_BRRR_DEVICE_ID
      - SANJA_BRRR_DEVICE_ID
    title: Fridge door open
    message: The fridge has been open for 45 seconds.
    thread_id: appliance-fridge
    icon_url: https://example.com/icons/fridge.png
    open_url: homeassistant://navigate/lovelace/kitchen
```

## Media Library images

Brrr accepts image URLs, while Home Assistant Media Library files normally require authentication. This integration can copy a selected local image to `/config/www/brrr/` and send Brrr an external `/local/brrr/...` URL.

This behavior is disabled by default and requires:

- **Allow temporary public Media Library images** enabled on the Brrr config entry.
- An externally reachable HTTPS Home Assistant URL.
- A local Media Library image no larger than 10 MB.

Home Assistant serves `/local` without authentication. Use only non-sensitive images. Generated filenames contain random, unguessable tokens. Expired files are removed when Brrr starts, hourly while it is loaded, and whenever another Media Library image is sent. The default retention is 24 hours.

To remove all generated public copies immediately, run **Brrr: Clean up public media** from **Developer Tools → Actions**.

For reusable icons, placing intentionally public files under `/config/www/brrr-icons/` and using their external HTTPS URLs is simpler and avoids cache copies.

## Removing the integration

Remove all Brrr entries under **Settings → Devices & services → Brrr Notifications**, restart Home Assistant, and delete `/config/custom_components/brrr`. Generated public files, if any, are in `/config/www/brrr` and can be deleted separately.

## Privacy and security

- Webhook keys are stored in the Home Assistant config entry and sent to Brrr using the `Authorization: Bearer` header.
- Keys are never included in action data or diagnostics.
- Icon and image URLs are sent to Brrr.
- Media Library export creates temporary unauthenticated public copies with random filenames; it is opt-in.
